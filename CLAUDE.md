## Repository Overview

A full-stack Security Operations Center (SOCC) training simulator built with Node.js/Express backend and React/TypeScript/Vite frontend. Features real-time multiplayer training sessions using Socket.io, invite code authentication, role-based access control, and comprehensive audit logging.

## Development Commands

### Setup & Installation
```bash
npm install                  # Install backend dependencies
npm run install:client       # Install frontend dependencies
cp .env.example .env         # Create environment config
npm run migrate              # Run database migrations
node server/database/init.js # Initialize database with default data
```

### Development Servers
```bash
npm run dev          # Start both backend (port 3001) and frontend (port 3000)
npm run dev:server   # Start backend only
npm run dev:client   # Start frontend only
```

### Building & Testing
```bash
npm run build        # Build frontend for production (TypeScript + Vite)
npm run lint         # Run ESLint on frontend code
npm run lint:fix     # Auto-fix frontend linting issues
npm run test         # Run frontend tests (Vitest)
npm run test:watch   # Run frontend tests in watch mode
```

### Database Management
```bash
node server/database/init.js                      # Initialize database
tail -f logs/combined.log                        # View application logs
tail -f logs/error.log                           # View error logs
cp data/socc-training.db data/backup-$(date).db  # Backup database
```

## Architecture

### Backend (Node.js/Express)
- **server/index.js**: Main server file with Socket.io configuration, game state management, and real-time matchmaking logic
- **server/database/**: Database initialization and migration scripts (SQLite)
- **server/models/**: Data models (User, Scenario, GameSession, InviteCode, OfflineSession)
- **server/routes/**: API route handlers (auth, scenarios, admin, offline)
- **server/middleware/auth.js**: JWT authentication and role-based authorization

### Frontend (React/TypeScript/Vite)
- **client/src/App.tsx**: Main application component with routing
- **client/src/components/**: React components for UI
  - `auth/`: Login, registration components
  - `admin/`: Admin dashboard and management interfaces
  - `offline/`: Offline training mode components (OfflineMode, PlayerAssignment)
  - `GameRoom.tsx`: Real-time game interface
  - `Lobby.tsx`: Player matchmaking lobby
  - `UserDashboard.tsx`: User progress and training history
- **client/src/contexts/**: React context providers

### Key Technical Patterns

**Real-time Multiplayer**: Socket.io manages player matchmaking, game sessions, and chat messaging. The server maintains `waitingPlayers` array and `activeGames` Map. When two players join, they're matched, assigned roles (responder/caller), and given a scenario.

**Authentication Flow**:
1. Invite code-based registration (codes are pre-generated by admins)
2. JWT tokens for session management
3. Socket.io authentication middleware validates tokens on connection
4. Role-based middleware protects API endpoints (trainee/trainer/admin)

**Game State Management**: Each game session has:
- Unique gameId (UUID)
- Two players with assigned roles (responder or caller)
- Scenario with scripts and goals
- Real-time chat messages stored in database
- Performance tracking and session history

**Offline Training Mode**: Manual session management for in-person/remote training. Trainers create sessions, add player names manually, and system automatically pairs players with random role assignment. Each player gets a unique cryptographic access code (8 chars) to view their assignment without authentication. Full assignment details (role, partner, scenario script/goals) can be copied for distribution.

**Database Schema**: SQLite with tables for users, invite_codes, scenarios, game_sessions, participants, audit_logs, offline_sessions, and offline_players. The invite code system supports email restrictions and role assignment. Offline mode uses cryptographically secure access codes for player authentication.

## Environment Configuration

Required `.env` variables:
- `NODE_ENV`: Set to "development" or "production"
- `PORT`: Backend server port (default: 3001)
- `FRONTEND_URL`: Frontend origin for CORS (default: http://localhost:3000)
- `DATABASE_PATH`: SQLite database file path
- `JWT_SECRET`: Secret for JWT token signing (CHANGE IN PRODUCTION)
- `SESSION_SECRET`: Express session secret (CHANGE IN PRODUCTION)
- `REQUIRE_INVITE_CODES`: Enable/disable invite code requirement (true/false)

## Important Implementation Details

1. **Default Admin Code**: Initial admin invite code "ADMIN2024" is created during migration (expires in 365 days, email: admin@socc-training.com)

2. **Scenario Loading**: Scenarios are loaded from database on startup. Falls back to hardcoded defaults if database is empty. 70% common scenarios, 30% uncommon scenarios.

3. **Socket Authentication**: Custom Socket.io middleware validates JWT tokens from `socket.handshake.auth.token` and attaches user object to socket.

4. **Session Management**: Express sessions stored in SQLite (`data/sessions.db`) with 24-hour expiration.

5. **Frontend Proxying**: Vite dev server proxies `/api` requests to backend (port 3001), configured in `client/vite.config.ts`.

6. **Audit Logging**: Winston logger writes to `logs/combined.log` and `logs/error.log`. All user actions and game events are logged.

## Security Considerations

- Change default JWT_SECRET and SESSION_SECRET in production
- Enable HTTPS in production (set `NODE_ENV=production`)
- Rate limiting configured for all `/api/*` endpoints (100 requests per 15 minutes)
- Helmet.js configured with Content Security Policy
- Passwords hashed with bcrypt (configurable rounds via BCRYPT_ROUNDS)
- HTTP-only cookies with secure flag in production
